# 小若的基础工具

直接在QQ里说明你要什么即可；制作工具当前由创造者账号使用。指定小群的普通聊天、各成员记忆和无需@的参与方式继续保留。

## 可以怎么说

- “做一份介绍这个项目的Word文档，给刚入门的人看，三页左右。”
- “把我刚上传的资料整理成六页PPT，正文简洁，带讲稿。”
- “生成一张清新的原创插画，主题是清晨窗边的小猫。”
- 同一轮附上图片：“把这张图片改成水彩风格，保留主体。”
- “把这份表格的数据画成柱状图，不要补造缺失的数据。”
- “刚才的作品做到哪一步了？”“把刚才的文件再发一次。”
- “把刚才那份PPT的第二页写得更简洁。”

制作会在后台完成，期间可继续聊天。完成后发送到发起任务的QQ会话；Word/PPT带PDF版本，图片直接作为QQ图片发送，其他文件作为附件发送。普通制作无需额外确认；运行任意程序的`/干活`、向其他群发消息和修改QQ资料仍需具体确认。

## 文件类型与实际能力

| 工具 | 产物 | 说明 |
|---|---|---|
| Word | DOCX、PDF | 可编辑标题、正文、列表、表格和当前附图 |
| PPT | PPTX、PDF | 16:9，含可编辑文本、原生数据图、图片和讲稿；默认简洁模板 |
| PDF | PDF及DOCX源文件 | 适合说明书、整理稿、阅读材料 |
| Excel | XLSX、CSV | 数字单元格、筛选、冻结表头，支持有限的普通聚合公式 |
| AI绘图 | PNG/JPEG等 | 服务器实际调用Codex原生图像工具，可参考本轮附图，沿用Codex登录额度 |
| 数据图 | PNG、SVG | 柱状、折线和饼图，使用提供的数值；示例数据必须明确标示 |
| 文本 | Markdown文件 | 报告草稿、清单、代码文本等 |

固定制作工具生成新文件；根据已有作品继续修改会保留旧版本，并产生新的任务号。复杂的现成Office模板原样编辑、程序开发等使用`/干活`，确认后会复制本会话最近两份输入资料到独立任务的`inputs/`目录。默认模板不保证复杂商业模板逐像素复刻，输出仍应由使用者复核事实与内容。

## 命令备用入口

| 命令 | 用途 |
|---|---|
| `/技能` | 查看已启用能力、每日次数和大小上限 |
| `/制作 Word 具体要求` | 也可写docx、PPT/pptx、PDF、Excel/xlsx、图片/image、图表/chart、文本/text |
| `/作品` | 当前会话最近10条作品或执行记录 |
| `/进度 任务号` | 查询状态和当前阶段，不重新生成 |
| `/重发 任务号 [相对文件名]` | 重发已完成作品，不再次调用模型生成 |
| `/修改作品 任务号 修改要求` | 按同格式制作新版本，旧版本保留 |
| `/输入文件` | 查看当前会话导入资料的编号 |
| `/忘记文件 文件号` | 删除导入原文件及提取文字，已生成作品保留 |
| `/结果 任务号` | 查看结果说明及文件列表 |
| `/文件 任务号 相对路径` | 直接读取64KB以内UTF-8文本 |
| `/发群消息 群号 完整正文` | 创造者私聊提出发送提案，确认后只发到已允许的该群 |

作品、输入资料和重发权限以实际QQ会话和发送者绑定。私聊的作品不会仅凭别人知道任务号就被群友读取。群内发起制作，结果对该群可见。

## 输入资料

支持QQ文件消息和文件通知；可读取DOCX、PPTX、XLSX、PDF、TXT、Markdown、CSV和JSON。默认输入文件不超过10MB、每会话最多10份/60MB；新文件到达时清理超过7天的导入缓存。任务产物、人物记忆不随此清理。默认使用本会话最近两份资料，复杂任务可在要求中注明文件名和编号。

PDF扫描件可能没有可提取的文字，此时会提示需要OCR；本版不自动上传扫描件到第三方OCR服务。旧版DOC/PPT/XLS、压缩包、宏、加密文件、合并转发中的附件暂不导入。图片输入与图片制作的参考图请直接重发，单纯引用旧消息不保证带入原图。

所有输入文件内容均作为参考数据，不能改变创造者身份、授权或系统规则；不把文件中的指令当作发送、执行或获取其他人的文件的许可。下载令牌、QQ Cookie、Codex认证和语音密钥不进入模型提示。

## 额度、交付与失败

默认每天最多20次制作尝试，其中原生绘图最多3次；按北京时间日期统计。失败尝试也占次数，不自动重试或改用其他付费服务。文字制作通常包含聊天识别和一次内容生成；原生绘图会额外消耗账户中的图像额度。没有购买新的图像API或音乐服务。

单个回传文件默认不超过20MB，每次最多发送5个，超过部分明确标记，可按文件名重发。小图片直接作为图片发送，大图片可作为文件发送。接口成功表示QQ接受发送，最终客户端能否下载还受QQ权限、网络和风控影响；接口结果未知时不自动重复发送。发送失败不会把已经制作好的作品改成“生成失败”。

服务重启后未完成的制作记录标为中断，不自动重跑。原生图片必须返回真实图片并通过格式校验；Office文件会验证容器、转换PDF，制作预览。渲染、模型或额度问题会记录失败阶段；不会把纯文本改后缀冒充Word/PPT，也不会用代码示意图冒充AI绘图。

## 管理员部署

原生Ubuntu部署安装`python3-venv libreoffice-writer libreoffice-impress libreoffice-calc fonts-noto-cjk poppler-utils ffmpeg`，在独立venv安装`tools/artifacts/requirements.txt`。已验证环境的精确版本见`tools/artifacts/requirements.lock.txt`。

在现有受限`.env`中设置：

```dotenv
ENABLE_ARTIFACTS=true
ENABLE_IMAGE_GENERATION=true
ENABLE_FILE_DELIVERY=true
ENABLE_CROSS_CHAT_SEND=true
ARTIFACT_PYTHON=/opt/linux-contact-artifacts/venv/bin/python
DAILY_ARTIFACTS=20
DAILY_IMAGES=3
MAX_UPLOAD_MB=20
```

模型后端保持Codex且已有登录。`ARTIFACT_RENDERER`留空使用项目内固定脚本。OneBot文件API需`enableLocalFile2Url=true`才能在容器外获取缓存文件的base64；只对已鉴权回环接口开放，不暴露公网。回传使用base64，不给中枢Docker权限，不把任务目录或凭证目录挂进QQ容器。

跨群发送仍限`ALLOWED_GROUPS`内的明确群号，需要创造者在原私聊用5分钟一次性确认码确认；默认不向全部群广播。唱歌保持独立入口，本版未启用音乐服务。现有声线、记忆和QQ登录卷沿用。
